## Executive Summary
Generative AI tools (Claude, ChatGPT, Gemini, Copilot) accelerate scaffolding, boilerplate generation, and CLI parsing. However, AI models routinely hallucinate critical networking primitives, misapply IEEE / RFC standards, produce syntactically defective Cisco IOS configurations, and fail to calculate physical layer power budgets correctly.

This audit log documents **three concrete, verified instances** of flawed networking code generated by AI during the development of NetArchitect. Each incident report details the prompt, buggy code, root cause, packet flow failure analysis, and our verified technical remediation.

## Audit Incident 1: Router-on-a-Stick Subinterface Omission of IEEE 802.1Q Encapsulation

- **Component:** `netarchitect/engines/config_generator.py` (Cisco IOS Configuration Generator)
- **Severity:** CRITICAL (Total inter-VLAN routing failure; Cisco IOS CLI syntax error)
- **Standard Reference:** IEEE 802.1Q (VLAN Tagging & Trunking), Cisco IOS-XE Subinterface Routing

### 1. The Prompt Given to AI
> *"Generate copy-paste ready Cisco IOS router configurations for Router-on-a-Stick inter-VLAN routing given a list of VLSM subnet allocations with assigned VLAN IDs."*

### 2. Flawed AI Code Generated
```cisco
! Buggy AI-generated router configuration
interface GigabitEthernet0/0.10
 description Gateway for Engineering (10.10.0.0/23)
 ip address 10.10.0.1 255.255.254.0
 no shutdown
!
interface GigabitEthernet0/0.20
 description Gateway for Admin (10.10.6.0/25)
 ip address 10.10.6.1 255.255.255.128
 no shutdown
```

### 3. Root Cause Analysis
The AI model treated a Cisco router subinterface like a standard physical interface, directly attaching the `ip address` command. In Cisco IOS / IOS-XE, a subinterface is fundamentally virtual and multiplexes multiple VLAN tags over a single physical parent link. Cisco IOS strictly requires the `encapsulation dot1Q <vlan_id>` command to bind the subinterface to an 802.1Q VID *before* the IP routing engine will accept an IP address. Furthermore, the AI failed to emit the parent physical interface `GigabitEthernet0/0` with `no shutdown` and `no ip address`, leaving the physical link administratively down.

When pasted into Cisco Packet Tracer or a Cisco IOS router, the terminal immediately aborts with:
```text
Router(config)# interface GigabitEthernet0/0.10
Router(config-subif)# ip address 10.10.0.1 255.255.254.0
% Configuring IP routing on a LAN subinterface is only allowed if that
subinterface is already configured as part of an 802.10, 802.1Q, or ISL vLAN.
```

### 4. Packet Flow & Failure Mode Analysis
```
[Host A: 10.10.0.50 (VLAN 10)]
       │
       ▼ (Untagged frame on Access Port)
[Access Switch: Acc-SW1 (Port Fa0/2)]
       │ (Inserts 4-byte 802.1Q tag: TPID=0x8100, VID=10)
       ▼ (802.1Q Tagged Trunk)
[Core Switch: Core-SW1 (Trunk Uplink)]
       │ (Tagged Ethernet Frame VID=10 forwarded)
       ▼
[Core Router: Core-RTR1 (GigabitEthernet0/0)]
       │
       ├── PHYSICAL LAYER: Parent Gi0/0 is administratively SHUTDOWN! (Frame dropped at NIC).
       └── LAYER 2/3 PARSER: Even if un-shut, without `encapsulation dot1Q 10`,
           the router's MAC demux has no VID mapping table entry for VID=10.
           The frame matches no active layer 3 interface and is SILENTLY DROPPED.
           Host A receives: "Destination Host Unreachable" (ICMP Type 3, Code 1).
```

### 5. Verified Engineering Remediation
We introduced the `encapsulation_dot1q` attribute into `InterfaceConfig`, configured the parent physical trunk interface (`GigabitEthernet0/0`) with `no shutdown`, and enforced ordering so `encapsulation dot1Q <vlan_id>` is written prior to `ip address`:

```cisco
! Corrected, Verified Configuration
interface GigabitEthernet0/0
 description Trunk link to Core-SW1 (Router-on-a-Stick)
 no shutdown
!
interface GigabitEthernet0/0.10
 description Gateway for Building-A Engineering (10.10.0.0/23)
 encapsulation dot1Q 10
 ip address 10.10.0.1 255.255.254.0
 no shutdown
!
```
**Verification:** Validated by automated test `test_router_subinterface_encapsulation_dot1q` in `tests/test_all.py` and demonstrated in all exported `.cfg` files.

## Audit Incident 2: Transceiver Mismatch & KeyError on Forced Single-Mode Fiber

- **Component:** `netarchitect/engines/media_engine.py` (L1 Physical Media & Link Budget Engine)
- **Severity:** HIGH (Application crash on valid input; invalid physical optical calculations)
- **Standard Reference:** IEEE 802.3ae (10GBASE-LR / 10GBASE-ER), IEEE 802.3an (10GBASE-T)

### 1. The Prompt Given to AI
> *"Implement media selection logic that validates user-forced media choices against physical distance limits and computes optical power budgets."*

### 2. Flawed AI Code Generated
```python
# Buggy AI code in decide_media()
medium, transceiver, max_reach, ieee_std = _select_medium(link.distance_m)

if link.forced_medium is not None:
    medium = link.forced_medium
    if medium == MediaType.CAT6A:
        transceiver, max_reach, ieee_std = (
            TransceiverType.RJ45_10GBASET, _CAT6A_MAX_M, "IEEE 802.3an"
        )
    elif medium == MediaType.OM4_MMF:
        transceiver, max_reach, ieee_std = (
            TransceiverType.SFP_10GBASESR, _OM4_MAX_M,
            "IEEE 802.3ae (10GBASE-SR, 850 nm VCSEL)",
        )
    # NOTE: AI omitted `elif medium == MediaType.OS2_SMF:` branch entirely!

# Later in decide_media():
if medium in (MediaType.OM4_MMF, MediaType.OS2_SMF):
    specs = _TRANSCEIVER_SPECS[transceiver]  # CRASH!
```

### 3. Root Cause Analysis
Single-Mode Fiber (OS2 SMF) can physically be deployed over any distance, including short campus runs (< 100m or 101–400m), when high-security or future-proofing is required. However, the AI only provided override branches for `CAT6A` and `OM4_MMF`. 
- If a user forced `OS2_SMF` on a 50m link, `_select_medium(50)` initially set `transceiver = RJ45_10GBASET`. Because there was no `OS2_SMF` branch, `transceiver` remained `RJ45_10GBASET`.
- When calculating the optical link budget, the code looked up `_TRANSCEIVER_SPECS[RJ45_10GBASET]`. Since copper RJ-45 has no optical specs, Python raised `KeyError: <TransceiverType.RJ45_10GBASET>`.
- Furthermore, on a 250m link with forced SMF, `transceiver` remained `SFP_10GBASESR` (850nm VCSEL), causing the optical budget to calculate with 3.5 dB/km OM4 attenuation instead of 0.35 dB/km OS2 fiber attenuation!

### 4. Physical Layer Failure Analysis
```
[Transmitter (Tx): SFP+ 10GBASE-SR (850 nm VCSEL)]
       │
       ▼ (850 nm Multimode Core: 50 µm beam aperture)
================ Optical Splice / Connector ================
       ▼ (OS2 Single-Mode Core: 9 µm narrow aperture)
[Receiver (Rx): Photodiode Receiver]

Physical Defect:
  1. Core Diameter Mismatch: 50 µm to 9 µm introduces an instantaneous
     insertion loss > 15–20 dB due to beam clipping at the ferrule interface.
  2. Dispersion: 850 nm VCSEL wavelength suffers massive attenuation and
     differential mode delay when launched into standard G.652 SMF.
  3. Result: Rx power drops below -14.4 dBm sensitivity threshold. Bit Error Rate (BER)
     exceeds 10^-12, inducing link flapping and continuous FCS CRC frame drops.
```

### 5. Verified Engineering Remediation
We added the comprehensive `MediaType.OS2_SMF` branch in `decide_media`, distinguishing short-haul LR (≤ 10 km) from extended-haul ER (≤ 40 km):

```python
elif medium == MediaType.OS2_SMF:
    if link.distance_m <= 10_000:
        transceiver, max_reach, ieee_std = (
            TransceiverType.SFP_10GBASELR,
            10_000.0,
            "IEEE 802.3ae (10GBASE-LR, 1310 nm)",
        )
    else:
        transceiver, max_reach, ieee_std = (
            TransceiverType.SFP_10GBASEER,
            40_000.0,
            "IEEE 802.3ae (10GBASE-ER, 1550 nm)",
        )
```
**Verification:** Regression test `test_forced_os2_smf_short_link` executes in `tests/test_all.py`, confirming zero KeyError, correct transceiver assignment, and positive link margin.

## Audit Incident 3: Inverted Wildcard Mask Confusion & Extended ACL Structural Formatting

- **Component:** `netarchitect/engines/config_generator.py` (ACL Generation)
- **Severity:** HIGH (Security policy bypass / permit unintended subnets)
- **Standard Reference:** RFC 1918, RFC 950, Cisco IOS Extended Access Control Lists

### 1. The Prompt Given to AI
> *"Format Cisco extended ACLs that permit traffic from allocated subnets using their subnet masks."*

### 2. Flawed AI Code Generated
```cisco
! Flawed AI-generated ACL logic:
ip access-list extended PERIMETER-FILTER
 10 permit ip 10.10.0.0 255.255.254.0 any

 20 permit ip 10.10.2.0 255.255.255.0 any
```

### 3. Root Cause Analysis
AI models consistently confuse **Subnet Masks** (where 1 bits match network and 0 bits match host) with **Cisco Inverted Wildcard Masks** (where 0 bits mean 'must match' and 1 bits mean 'ignore / wildcard'). 
- Supplying `10.10.0.0 255.255.254.0` as an ACL filter in Cisco IOS means: *"Match any IP where the 3rd octet has bit 0 set to 0, ignoring the 1st and 2nd octets"*. This allows foreign IP addresses like `192.168.0.x` or `172.16.0.x` to bypass the firewall completely!
- In addition, the AI implementation in `_gen_acl` used `if entry.sequence == acl.entries[0].sequence:` inside the entry loop, writing empty blank lines between rules and breaking standard Cisco IOS configuration indentation.

### 4. Packet Flow & Security Breach Analysis
```
[Attacker IP: 198.51.100.10 (External Public Host)]
       │
       ▼ (Ingress at Edge Router WAN Interface)
[Evaluated Against Buggy ACL: `permit ip 10.10.0.0 255.255.254.0 any`]
       │
       ├── Bitwise Check:
       │     Packet IP:    198.51.100.10   (11000110 . 00110011 . 01100100 . 00001010)
       │     Mask (Wild):  255.255.254.0   (11111111 . 11111111 . 11111110 . 00000000)
       │     Evaluation: Wildcard bits (1s) IGNORE octets 1 and 2 entirely!
       │     Octet 3 bit 0 must be 0 (100 is even -> bit 0 is 0 -> MATCHES!)
       │
       └── POLICY OUTCOME: PACKET PERMITTED! (FIREWALL BYPASS).
           Malicious ingress penetrates the internal corporate subnet.
```

### 5. Verified Engineering Remediation
We mathematically inverted the subnet mask via bitwise XOR with `0xFFFFFFFF`:
$$\text{Wildcard Mask} = \text{Subnet Mask} \oplus \text{0xFFFFFFFF}$$
And corrected the ACL formatting engine:

```cisco
! Corrected Cisco IOS Extended ACL
ip access-list extended PERIMETER-FILTER
 10 permit tcp any any ! Permit established return sessions
 20 permit ip 10.10.0.0 0.0.1.255 any ! Permit Building-A Engineering internal traffic
 30 permit ip 10.10.2.0 0.0.0.255 any ! Permit Building-B Labs internal traffic
 ...
 120 deny ip any any ! Implicit deny-all unmanaged ingress
!
```
**Verification:** Unit tests `test_wildcard_mask` and `test_mask_wildcard_complement` prove that $\text{Mask} \lor \text{Wildcard} = \text{0xFFFFFFFF}$ and $\text{Mask} \land \text{Wildcard} = 0$ for all prefixes /1 to /32. Verified by test `test_perimeter_acl_generated_with_wildcards`.
